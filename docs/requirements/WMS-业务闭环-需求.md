# WMS 业务闭环 需求

> 版本：v1.0　日期：2026-11-07　提出人：项目负责人
> 关联规划：`docs/WMS-V1.0-业务闭环-规划.md`

## 背景与目标

当前 WMS 有 21 张业务表、84 个接口、21 个列表页，但**全部是 CRUD**：21 个 `*ServiceImpl` 各 17 行空壳，0 个 Mapper XML，业务侧 0 处 `@Transactional`。

后果是一单业务跑不通：一张入库单收货上架，库存不会变；一张出库单发运，库存不会减、流水不会写、明细的 `shipped_qty` 也不会自洽。所有数量字段只能靠人工在弹窗里手填，数据之间没有因果关系。

**本版目标**：让「单据 → 库存 → 流水」三者产生因果关系，跑通入库、出库、盘点三条闭环。

**不做会怎样**：这套系统只能当数据录入台账用，任何一个真实仓库都无法使用。

## 功能点

### P0-1 库存核心（地基）

| 编号 | 功能点 | 优先级 | 说明 |
|---|---|---|---|
| F-01 | 库存变动统一入口 | P0 | 增/减/分配/释放分配/冻结/解冻六类变动，只能经 `InventoryCoreService`，禁止直接 `updateById` 改 `qty_*` |
| F-02 | 库存流水自动记录 | P0 | 每次变动同事务写一条 `wms_inventory_txn`，含 `qty_before`/`qty_after`/`ref_order_no` |
| F-03 | 可用量口径修正 | P0 | `qty_available` 改为 `on_hand - allocated - locked`；`lock_type` 去掉 `PICK`，只留 `STOCKTAKE/QC/TRANSFER` |
| F-04 | 库存记录软删后可复用 | P0 | 同 `(warehouse, owner, sku, location, batch)` 的已软删记录，收货时**复活**而非插入新行（否则撞 `uk_inv`） |

### P0-2 入库闭环

| 编号 | 功能点 | 优先级 | 说明 |
|---|---|---|---|
| F-05 | 收货登记 | P0 | 分批收货，累加 `received_qty`，行状态 `PENDING/PARTIAL/DONE` |
| F-06 | 上架 | P0 | 指定目标库位，按批次/效期建库存记录，库存增加 + 流水 `PUTAWAY` |
| F-07 | 入库单状态流转 | P0 | `CREATED → IN_TRANSIT → RECEIVING → RECEIVED → PUTAWAY_DONE`，非法流转拒绝 |

### P0-3 出库闭环

| 编号 | 功能点 | 优先级 | 说明 |
|---|---|---|---|
| F-08 | 库存分配（FEFO） | P0 | 按效期升序选批，写 `wms_allocation`，增加 `qty_allocated`；**不动 `on_hand`** |
| F-09 | 拣货确认 | P0 | 累加 `picked_qty`，同时减 `qty_allocated` 与 `qty_on_hand`，流水 `PICK` |
| F-10 | 发运 | P0 | 写发运记录，累加 `shipped_qty`，单据 `SHIPPED` |
| F-11 | 取消分配 | P0 | 释放 `qty_allocated`，`wms_allocation.status=0`，单据回 `CREATED` |
| F-12 | 出库单状态流转 | P0 | `CREATED → ALLOCATED/PARTIAL → PICKING → PICKED → SHIPPED` |

### P0-4 盘点闭环

| 编号 | 功能点 | 优先级 | 说明 |
|---|---|---|---|
| F-13 | 创建盘点单并快照 | P0 | 按范围生成 `wms_stocktake_item`，`system_qty` 取创建时快照 |
| F-14 | 冻结/解冻 | P0 | 冻结期 `qty_locked` 上升，该库存不可再被分配 |
| F-15 | 录入实盘 | P0 | 写 `counted_qty`/`counted_by`/`counted_at`，`diff_qty` 由生成列自动算 |
| F-16 | 确认差异调整 | P0 | 按 `diff_qty` 调整 `on_hand`，流水 `ADJUST`，释放冻结 |

### 前端（4 个页面，其余 17 个主数据页不动）

| 编号 | 功能点 | 优先级 | 说明 |
|---|---|---|---|
| F-17 | 入库单页业务操作 | P0 | 新增「收货」「上架」按钮与弹窗；`received_qty`/`putaway_qty` 列只读 |
| F-18 | 出库单页业务操作 | P0 | 新增「分配」「拣货」「发运」「取消分配」；数量列只读 |
| F-19 | 盘点单页业务操作 | P0 | 新增「冻结」「录入实盘」「确认调整」；差异列高亮 |
| F-20 | 库存页只读化 | P0 | `qty_*` 全部只读，去掉「新增/删除」按钮 |

## 边界与异常

| 场景 | 期望行为 |
|---|---|
| 收货数量为空或 ≤0 | 拒绝，提示「收货数量必须大于 0」 |
| 累计收货 > 预期数量 | 拒绝，提示「收货数量超出预期，预期 X，已收 Y」 |
| 上架数量 > 已收数量 | 拒绝，提示「上架数量不能大于已收数量」 |
| 上架到不存在的库位 | 拒绝，提示「库位不存在或已停用」 |
| 出库分配时库存不足 | **部分分配**：能分多少分多少，行状态 `PARTIAL`，单据 `PARTIAL`；不报错 |
| 完全无库存可分配 | 单据保持 `CREATED`，返回「无可用库存」提示 |
| 拣货数量 > 已分配数量 | 拒绝，提示「拣货数量不能大于已分配数量」 |
| 发运时存在未拣完的行 | 拒绝，提示「第 N 行未拣完，不能发运」 |
| 非 `CREATED` 状态重复分配 | 拒绝，提示「当前状态不允许分配」 |
| 重复提交同一收货请求（幂等键相同） | 返回上次结果，不重复累加 |
| 盘点期间该库存被发运导致盘亏为负 | 确认时拒绝，提示「库存已变为负数，请重新盘点」 |
| 盘点单未冻结就录实盘 | 允许录入，但确认时提示先冻结 |
| 库存记录已被软删仍要收货 | 复活该行并累加，不插入新行（`uk_inv` 约束） |
| 单据不存在 | HTTP 200 + `code:40400`，msg「入库单不存在」 |
| 未登录 | HTTP 200 + `code:401`，前端跳登录 |

## 验收标准

**P0-1 库存核心**
- [ ] F-01 六类变动全部走 `InventoryCoreService`，`grep -rn "setQtyOnHand\|setQtyAllocated\|setQtyLocked"` 在 `service/impl` 下除该类外无命中
- [ ] F-02 任一次库存变动后，`wms_inventory_txn` 必增一行，且 `qty_before + qty_change = qty_after`
- [ ] F-03 冻结 100 后可用量显示 0（改前显示 100）
- [ ] F-04 软删一条库存记录后收货同库位同批次 → 成功且行数不增加、`deleted` 回 0
- [ ] 并发：50 线程各扣 1 件（初始 100）→ 成功恰好 100 次，`on_hand=0`，流水 100 条，无负数

**P0-2 入库**
- [ ] F-05 3 行明细先收 2 行 → 单据 `RECEIVING`，2 行 `PARTIAL`，第 3 行 `PENDING`
- [ ] F-06 上架 2 行后 → 库存记录 2 条，`on_hand` 等于上架量，流水 2 条 `PUTAWAY`
- [ ] F-07 全部收齐 → `RECEIVED`；全部上架 → `PUTAWAY_DONE`；跳过收货直接上架 → 拒绝

**P0-3 出库**
- [ ] F-08 在库 10（A 批效期近 6 件 + B 批 4 件），出库 8 件 → 分配 A6+B2，`allocated=8`，`on_hand` 仍为 10
- [ ] F-09 拣货 8 件 → `on_hand=2`、`allocated=0`、流水 2 条
- [ ] F-10 发运 → 单据 `SHIPPED`，发运记录 1 条
- [ ] F-11 取消分配 → `allocated` 归 0，单据回 `CREATED`
- [ ] F-12 出库 12 件（库存仅 10）→ 分配 10，单据 `PARTIAL`

**P0-4 盘点**
- [ ] F-13 创建盘点单 → `system_qty` 与当前 `on_hand` 一致
- [ ] F-14 冻结后该库位可用量为 0，出库分配选不中它
- [ ] F-15 录实盘 98（账面 100）→ `diff_qty=-2`（生成列自动）
- [ ] F-16 确认 → `on_hand=98`，流水 1 条 `ADJUST -2`，锁定量归零，可用量恢复

**整体**
- [ ] 恒等式：每张库存记录 `on_hand = 该 SKU+库位+批次所有流水 qty_change 之和`
- [ ] 前端 4 个页面 console 零 error，业务按钮全流程可点通
- [ ] 主数据 17 个页面功能不回归（列表/新增/编辑/删除仍可用）
