V1.1 一键建库与门禁 · 效果图

运维 / CI 视角：scripts/db-init.sh 重建空库，scripts/verify.sh 一条命令跑完三层验证

db-init.sh 执行顺序

中文种子必须 --default-character-set=utf8mb4；脚本幂等，可重复执行；不会 DROP 库，不碰已有数据
0 CREATE DATABASE1 init_tables.sql2 init_sys_user.sql3 init_sys_flow.sql4 init_seed.sql5 init_menu.sql6 dict.sql7 V1.0__wms_inventory_core.sql（必须）8 V1.0__wms_seed.sql
第 7 步不能省：init_tables.sql 里 qty_available 仍是旧口径 on_hand - allocated，且不含 wms_request_log 表；省掉会同时造成「冻结期超卖」和「幂等端点全挂」。

verify.sh 门禁

步环节命令失败即停结果
1库表体检db 连通 + 34 表 + 生成列口径是PASS
2后端编译mvn -o package -DskipTests（7 模块）是BUILD SUCCESS
3起环境cloud-up.sh（不 --with-web，不重建库）是6 服务已注册
4端到端node scripts/e2e-cloud.mjs（含并发 step）是132/132
5对账node scripts/reconcile.mjs是0 差异
6前端编译NODE_OPTIONS= npm run build是DONE
7报告汇总各步耗时与证据路径—全绿
门禁脚本不调用 db-init.sh —— 重放建库脚本会干扰运行库；它只做「只读体检」。需要重建空库时由人工单独执行 db-init.sh。
